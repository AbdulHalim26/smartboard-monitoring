// Pin Konfigurasi
#define DHTPIN       4    // Data DHT11
#define DHTTYPE      DHT11
#define MQ135_AOUT   34   // Analog input MQ-135
#define MQ135_DOUT   35   // Digital input (tidak dipakai)
#define LED_RED      25   // LED indikator bahaya
#define LED_GREEN    26   // LED indikator normal
#define BUZZER       27   // Buzzer alarm
#define RELAY_PIN    17   // Relay kipas (active LOW)

// Koneksi WiFi
const char *WIFI_SSID  = "YOKA 4G";
const char *WIFI_PASS  = "123040506";
const char *SERVER_URL = "http://192.168.1.31:3000/api/telemetry";

// Inisialisasi di setup()
void setup() {
  Serial.begin(115200);
  pinMode(LED_RED, OUTPUT);
  pinMode(LED_GREEN, OUTPUT);
  pinMode(BUZZER, OUTPUT);
  pinMode(RELAY_PIN, INPUT);  // relay: off saat ngambang
  dht.begin();
  connectWiFi();
}

Catatan:
- Relay memakai active LOW: GPIO LOW = relay ON (kipas menyala)
- Saat GPIO = INPUT (ngambang) → relay OFF (pull-up internal 5V)


# ────────────────────────────────────────────────────────────
#  SLIDE 5: PROSES PEMBACAAN SENSOR
# ────────────────────────────────────────────────────────────

Loop utama (non-blocking, pakai millis):

  1. Baca sensor tiap 2 detik:
     - DHT11 → temperature (°C) + humidity (%)
     - MQ-135 → gas_value (ADC 0-4095)

  2. Evaluasi threshold lokal (offline-proof):
     - gas > 3500  → GAS alert
     - temp > 40   → TEMP alert
     - hum  > 75   → HUM alert
     → Aktifkan LED merah + buzzer + fan

  3. Kirim data ke server tiap 10 detik:
     POST /api/telemetry
     Body: {device_id, temperature, humidity, gas_value, fan_on, ...}
     Header: x-api-key: rahasia-untuk-esp32

  4. Cek WiFi berkala → reconnect jika putus

  5. Serial Monitor → perintah manual:
     hijau | merah | fan | buzzer | auto | autocloud | status

Pembacaan sensor:
  float temp = dht.readTemperature();
  float hum  = dht.readHumidity();
  int gas    = analogRead(MQ135_AOUT);


# ────────────────────────────────────────────────────────────
#  SLIDE 6: KIRIM DATA KE SERVER
# ────────────────────────────────────────────────────────────

void sendTelemetry() {
  HTTPClient http;
  http.begin(client, "http://192.168.1.31:3000/api/telemetry");
  http.addHeader("Content-Type", "application/json");
  http.addHeader("x-api-key", "rahasia-untuk-esp32");

  JsonDocument doc;
  doc["device_id"]    = "esp32-room-01";
  doc["temperature"]  = lastTemp;
  doc["humidity"]     = lastHum;
  doc["gas_value"]    = lastGas;
  doc["fan_on"]       = fanState;

  String body;
  serializeJson(doc, body);
  int code = http.POST(body);  // 201 = berhasil
  http.end();
}

Alur data:
  ESP32 → HTTP POST → Next.js API → validasi (Zod) → Supabase
                                                ↓
                                         Dashboard (real-time)

                  & ESP32 (REST + Realtime).
  C1. Actuator  : ESP32 polling (mode autocloud, 15 dtk) →

                  NORMAL = fan OFF + LED hijau.

                  dan prediksi ARIMA (+1/+2/+3 jam).
  D. Feedback   : data baru tiap 60 dtk dipakai retrain model supaya
                  tetap adaptif terhadap kondisi terbaru.


# ────────────────────────────────────────────────────────────
#  SLIDE 9: PROSESING DI DALAM ML (Feature Engineering)
# ────────────────────────────────────────────────────────────

[Gambar: flow_processing_in_ml.png]

Sebelum data masuk ke algoritma (Decision Tree / ARIMA), data
diolah lagi menjadi FITUR. Ini yang "reprocessing" di dalam ML:

  INPUT: DATA BERSIH (975 baris: temp, hum, gas, status)
      │
      ▼
  FEATURE ENGINEERING (compute_features)
  Untuk tiap sensor (temp/hum/gas) dibuat fitur turunan:
    • mean rolling 10 baris   →  …_mean10
    • standar deviasi rolling →  …_std10
    • selisih antar baris     →  …_delta
    • jam dalam sehari        →  hour
  ⇓ Total 13 kolom fitur (FEATURE_COLS)
      │
      ├──────── Decision Tree ──────────┐
      │  Split: fitur + label (status)   │
      │  Training (max_depth=6)          │
      │  predict_proba → confidence      │
      │  → NORMAL/WASPADA/BAHAYA        │
      │                                 │
      └───────── ARIMA ──────────────────┘
         Resample per jam (mean)
         ARIMA(1,1,1) + forecast(3)
         → prediksi +1/+2/+3 jam

Mengapa dibuat fitur turunan ini?
  - Karena kondisi ruangan tidak hanya dari nilai sesaat,
    tetapi juga dari TREN/pergerakannya (naik/turun cepat).
  - mean/std rolling menangkap tren & variabilitas.
  - delta menangkap seberapa cepat nilai berubah.
  - hour membantu mendeteksi pola berdasar jam (mis. siang
    lebih panas, dll).

Hasilnya: model lebih akurat daripada hanya pakai 3 nilai mentah.


# ────────────────────────────────────────────────────────────
#  SLIDE 10: MACHINE LEARNING — Decision Tree
# ────────────────────────────────────────────────────────────

Tujuan: Klasifikasi status ruangan
  Output: NORMAL / WASPADA / BAHAYA (+ confidence)

Algoritma: Decision Tree Classifier (scikit-learn)
  max_depth: 6  |  random_state: 42

Fitur input (13 kolom):
  temperature, humidity, gas_value
  temperature_mean10, temperature_std10, temperature_delta
  humidity_mean10, humidity_std10, humidity_delta
  gas_value_mean10, gas_value_std10, gas_value_delta
  hour (jam dalam sehari)

Ground truth (label training):
  Bukan dari data manual, tapi dari RULE-BASED threshold:
  temp≥36 → BAHAYA, temp≥33 → WASPADA, selainnya NORMAL
  (threshold hasil EDA dari data riil)

Training:
  - Data: 975 baris dari Supabase (24 jam terakhir)
  - Retrain otomatis tiap 60 detik
  - Model disimpan ke dt_classifier.joblib


# ────────────────────────────────────────────────────────────
#  SLIDE 11: MACHINE LEARNING — ARIMA Prediksi Tren
# ────────────────────────────────────────────────────────────

Tujuan: Prediksi suhu, kelembapan, gas untuk +1, +2, +3 jam ke depan

Algoritma: ARIMA (AutoRegressive Integrated Moving Average)
  Order: (1, 1, 1) — dari statsmodels
  Resample data per jam (1 jam = 1 titik)

Langkah:
  1. Ambil data 24 jam terakhir
  2. Resample per jam → rata-rata per jam
  3. Fit model ARIMA(1,1,1)
  4. Forecast 3 jam ke depan
  5. Simpan ke tabel ml_predictions di Supabase

Contoh output:
  Suhu  : +1 jam = 31.2°C, +2 jam = 31.4°C, +3 jam = 31.3°C
  Hum   : +1 jam = 68.5%,  +2 jam = 69.1%,  +3 jam = 69.3%
  Gas   : +1 jam = 104,     +2 jam = 106,     +3 jam = 105


# ────────────────────────────────────────────────────────────
#  SLIDE 12: AUTO-FAN (ESP32 Polling Supabase)
# ────────────────────────────────────────────────────────────

Mode autocloud:
  ESP32 polling tabel ml_classifications tiap 15 detik
  → Baca predicted_status terbaru dari Python ML
  → WASPADA/BAHAYA → nyalakan fan + LED merah + buzzer
  → NORMAL         → matikan fan + nyalakan LED hijau

Perintah Serial:
  autocloud  → aktifkan mode ini
  auto       → kembali mode sensor lokal
  hijau/merah → manual override

Keamanan:
  - Anon key Supabase hanya boleh baca (RLS policy SELECT)
  - Python backend menulis via service role
  - ESP32 hanya membaca klasifikasi (tidak menulis)
